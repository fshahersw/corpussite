# Trellis browser law captures

This collection preserves selected rendered law text from the user's signed-in Chrome session. It is separate from both the Firecrawl provider archive and original HTTP captures. No cookies, credentials, account identity, related case previews or unrelated URLs are exported. Legal source HTML is stored as inert data and never served as executable page content.

The first batch contains the 38 section pages linked by Trellis's Arizona Constitution Article 2 directory, plus the directory itself. `article_2_reconciliation.json` matches all 38 observed links to saved section captures and verifies raw/text hashes. It does not establish a current edition or a complete Arizona constitution. The original official-source collection's edition and body gaps remain in `reports/laws/`.

The next batch adds nine Article 12 (Counties) sections and three Article 16 (Militia) sections. All 12 match the exact child links in the two already saved Firecrawl directory captures. Their HTML directory containers, provider link lists and markdown agree on the 9+3 URLs. The browser collection now contains 51 captures: 50 law texts and the original Article 2 directory.

[The Article 12/16 reconciliation](reconciliations/20260913T194101027304Z_articles_12_16/summary.json) verifies all 12 raw, text and timestamp-excluded content hashes, exact raw `legal_text` equality, and both source-directory hashes. The new text totals 16,338 UTF-8 bytes, with no missing or unexpected child URLs and zero unresolved validation issues. Directory markdown comparison accounts explicitly for its existing Windows CRLF line endings while retaining the original file hashes. Reconciliation runs create new evidence directories; the earlier Article 2 evidence and the initial newline-comparison attempt remain unchanged.

## Files and verification

- `manifest.jsonl`: append-only capture versions with URL, observed title/heading, type, capture time, DOM selector, browser provenance, artifact hashes and observed law links.
- `raw/<sha-prefix>/<sha>.json`: selected DOM HTML, exact rendered text and law links.
- `text/<sha-prefix>/<sha>.txt`: UTF-8 text matching raw `legal_text` exactly.
- `article_2_reconciliation.json`: the bounded section-list comparison, not a statewide completion flag.
- `reconciliations/*_articles_12_16/`: append-only summaries and per-capture hash checks for the observed 9+3 child links; source-provider and browser provenance stay separate.
- `browser_access_history.jsonl` and `browser_access_20260913T125000Z.snapshot.json`: allowance observations and the byte-identical prior access record.

Archive v1.0.0 used `div.rule-header` for the initial section bodies. Version 1.0.1 requires that selector for `law_text` and the observed `div.profileBillingContainer` for `law_directory`. The document index validates both contracts and preserves `browser_rendered_dom` provenance. The archiver has six boundary/idempotency/tamper fixtures; index builder v1.4.0 passed 21 focused fixtures.

## Continue through the supported browser API

1. Read the browser documentation and inspect current Chrome tabs. Use the authorized signed-in Trellis session. The saved Article 2 directory is a handoff tab; locate it by its current URL, not a guessed tab ID. Check Account Overview's displayed content-view allowance before selecting a new batch. A login, account-limit, CAPTCHA or security barrier is a checkpoint, not authorization to bypass it.
2. Start `python -X utf8 scripts/trellis_browser_archive.py` from the workspace. It binds only `127.0.0.1` on a fresh port and prints the actual URL/PID. Keep this helper alive only while a browser batch is being saved. It performs no Trellis requests. Chrome's native `content.export()` was tried and returned unsupported; do not repeatedly retry that command.
3. Open the printed local URL in an agent browser tab. Read legal content only through supported CUA/browser DOM APIs. Navigate only to observed law links and deduplicate already-captured URLs against this manifest and the provider archive. Do not expand cases, documents, general URLs or query variants. For each leaf, verify its expected heading and complete legal container; for each directory, verify its single law-list container. Record content kind correctly.
4. Read the selected container's `outerHTML`, `innerText` and heading. The payload fields are `url`, `title`, `heading`, `legal_text`, `legal_html`, `observed_law_links` (URL/text pairs), `captured_at` (ISO timestamp with timezone), `content_kind`, `dom_selector`, and boolean `signed_in_observed`. Filter observed links to exact HTTPS `trellis.law/state-rules` paths without fragments or query strings. Do not copy whole account pages or related case/document previews.
5. Fill the local form's **Observed legal capture JSON** field and click **Save legal capture**. This writes only to this local collection. Wait for `#result` filtered by the exact expected source URL to become visible, then refresh the DOM snapshot and read the result. A navigation promise alone can return before the redirected result updates; an old success URL does not verify the new save. Require `saved` or `already_saved` and exact URL equality. On an uncertain result, inspect the real manifest before revisiting a law page.
6. Keep each browser tool batch small enough to finish within 60 seconds. Capture the directory used to enumerate any claimed completed section batch. Verify raw/text hashes and missing/unexpected URLs, then run the document index and scoped status builders after a meaningful batch. Original Firecrawl rows are unchanged: reconcile these separately saved URLs before a future provider restart to avoid duplicate acquisition, and never label browser DOM as a Firecrawl/HTTP response.
7. Close the local form tab and stop the exact verified loopback helper PID when the batch ends. Keep only a necessary law handoff tab. No independent background browser crawl is implied by this collection or by the receiver process.

# Agency safety and enforcement supplement (FDA first; CPSC from a local file)

Built 2026-09-19 in two rounds (the first was cut off by a session limit; round 2 reused every
saved original after re-verifying it against `receipts.jsonl`). Nothing here is a legal or medical
conclusion: a recall, warning letter, shortage or complete response letter is an agency record about
a product or firm, not proof of defect, causation or liability.

## What is in the folder

| File | Meaning |
|---|---|
| `seeds.jsonl` | The frozen URL list (12 seeds, 2 packets). Only these URLs were requested. |
| `fetch.py` | Bounded collector: one request per seed, `User-Agent LegalCorpusResearch/1.0`, per-host delay (30 s on www.fda.gov per its robots Crawl-delay, 2 s elsewhere), no retries, streamed to disk with SHA-256, one receipt per request. |
| `receipts.jsonl` | One line per request: status, headers, final URL, timestamps, bytes, sha256, saved path. 11 saved, 1 rejected (robots.txt 403, see gaps). |
| `packet1.log`, `packet2.log` | Collector output of the two packets (33 s and 32 s). |
| `raw/` | Original bytes exactly as received: `download.json` (openFDA bulk index), 9 openFDA bulk zips, 2 FDA.gov XLSX exports, `raw/local/Recalls.csv` (byte-identical copy of the user-supplied CPSC file), `raw/_rejected/` (the 403 body). |
| `gaps.json` | Barriers (hosts never contacted), items deliberately not acquired, and one acquisition deviation that needs a user decision. |
| `build.py` | Offline, re-runnable build: raw -> `agency_safety.sqlite3` + jsonl side files + `validation.json`. Never touches the network. |
| `agency_safety.sqlite3` | The supplement database (schema below). |
| `firm_names.jsonl` | One line per distinct normalised firm string with the verbatim spellings and per-dataset counts. |
| `edges.jsonl`, `unresolved.jsonl` | Relationship edges with explicit evidence; joins that could not be made, with the reason. |
| `files.json` | Registry of the original files the adapter may serve (file id, sha256, bytes, publisher URL, capture time). |
| `validation.json` | Uniform envelope; the adapter opens only when `status == "passed"`, `ready == true` and every data-file hash matches. |
| `integration_spec.json` | Adapter signatures, proposed routes with example responses, UI placement, edge description. Regenerated by `make_integration_spec.py`, which reads real responses through the adapter (offline). |
| `build.log` | Output of the last `build.py` run (per-dataset rows and elapsed seconds, then the gate summary). |
| `test_build.py` | Unit tests for the parsers and for the built outputs (skipped when the database is absent). |

Every record keeps the publisher's verbatim record (`raw_records`, zlib-compressed JSON of the row as
found) next to the normalised columns, so nothing is lost by the normalisation.

## Dates (kept separate, never merged)

- Enforcement: `recall_initiation_date` (firm began the recall), `center_classification_date` (FDA
  center classified it), `report_date` (appeared in the Enforcement Report), `termination_date`
  (empty while the recall is open). `published_at` = `report_date`.
- Drugs@FDA: every submission keeps its own `submission_status_date`; `original_approval_date` is
  derived (earliest ORIG submission with status AP) and labelled so.
- PMA: `date_received`, `decision_date`, `fed_reg_notice_date`.
- Warning letters: `posted_date` (FDA posted it) vs `letter_issue_date` (letter date). `published_at`
  = `posted_date`.
- FDA press list: `listed_date` (the export's undefined `Date` column); `published_at` stays unknown.
- CPSC local: `date` as found; `captured_at` unknown (no receipt; file-system dates are not evidence).
- Temporal block per record: `captured_at` = HTTP completion time of the original; `source_as_of` =
  openFDA `export_date` from `download.json` (bulk) or the export request date (XLSX);
  `published_at` per dataset as above; `effective_from`/`effective_to` always unknown (agency records
  have no effective date). Each value carries a `*_basis` string or null.

Non-calendar publisher dates (for example Orange Book "Approved Prior to Jan 1, 1982") are kept in the
`*_raw` column and not indexed as dates; `counts.date_values_not_calendar_dates_kept_raw` in
`validation.json` says how many.

## Firms and edges

`firm_names.jsonl` groups verbatim spellings by an exact normalised string (NFKC, upper-case,
`&` -> `AND`, punctuation removed, whitespace collapsed). No suffix stripping, no alias table, no
merging: "ACME CORP" and "ACME CORPORATION" stay two firms, and two legal entities that spell their
name the same way share one string. `firm:<slug>` ids are that string, nothing more.

`edges.jsonl` (`{"from","to","relation","basis","evidence"}`):
- `recalling_firm`: enforcement record -> `firm:<slug>` (publisher field `recalling_firm`);
- `application_sponsor`: Drugs@FDA application -> `firm:<slug>` (publisher field `sponsor_name`);
- `classified_under_regulation`: device classification -> `cfr:21:<part>.<section>` (publisher field
  `regulation_number`; the evidence notes whether the section exists in the eCFR Title 21 structure
  snapshot of 2026-09-16 saved by the regulations scout, when that snapshot is available).
Unresolvable joins (empty firm, empty or malformed regulation number) go to `unresolved.jsonl`.

## What the counts mean

`validation.json -> counts`: rows per dataset (equal to the publisher's `meta.results.total` and to
`download.json -> total_records` for every openFDA file, checked), `records_total`, `firm_strings`
(distinct normalised strings, not entities), `edges` and `unresolved` per relation,
`duplicate_native_ids_suffixed` (publisher ids that repeat inside one file; the repeats get `~2`,
`~3`...), and the date-value ranges of the list exports.

## Limits

- openFDA data is public domain (CC0) with the publisher disclaimer "Do not rely on openFDA to make
  decisions regarding medical care ... assume all results are unvalidated"; the disclaimer is stored
  in every dataset's qualification. Bulk exports are point-in-time (`export_date`), not live queries.
- FAERS and MAUDE event files were not downloaded (task exclusion); `device/510k`, `device/recall`,
  `cosmetic/event`, `food/event` are the scout's second slice and are not here.
- The FDA.gov warning-letters export returned exactly 1,000 rows and is therefore capped by the
  publisher (not the complete list); the press-recall export returned 1,041 rows and its
  completeness was not verified. Both are list rows only, with no links or letter text.
- cpsc.gov, saferproducts.gov, nhtsa.gov (and api.nhtsa.gov) answered robots.txt with 403 for the
  scout and were not contacted; the CPSC dataset comes from a local CSV of unknown provenance and was
  never checked against the publisher.
- Acquisition deviation (needs a user decision, see `gaps.json`): `download.open.fda.gov/robots.txt`
  answered HTTP 403 (S3 AccessDenied XML) and the first run of `fetch.py` treated that as "no robots
  file" and fetched the 9 bulk zips (all HTTP 200, URLs published in `download.json`). `fetch.py`
  was corrected to stop at a 403; the files were kept unmodified.
- No third-party package was installed: `openpyxl` 3.1.5 was already present and is used to read the
  two XLSX exports.

## What each column means (all values are derived; `*_basis` names the evidence)

- `record_id`, `dataset`, `group_name`: copied from `records`.
- `original_kind`: `records.kind` verbatim. `base_kind`: the kind without the `ocr_text`/`document_text`/`law_text` modifiers. `kind_flags`: JSON list of those modifiers (+ `multi_kind`).
- `derived_category` / `categories` / `category_basis` (D01, D10, D11): primary category and JSON list of all memberships (`facet_categories` mirrors the list). Values: statutes, rules, constitutions, regulations, forms, guidance, directories, judges, other.
  - focused: from the retained `payload.categories_json` tokens (statutes, constitution, state_rule/court_rules/local_rules, administrative_code, county/court directory kinds, ...). Review states (`needs_content_review`, `law_document_title_evidence_needs_review`) are never categories. For the Trellis state-rules collections the URL path segment (`/state-rules/<st>/constitution|code|statutes|administrative-code|...`) decides the top category before the payload category (D11): 584 constitutions, 586 statutes, 114 regulations, 123 rules. Blank retained category (4 records) falls back to `classify(kind)` and stays `other` with that basis.
  - seeger: from `resource_kind`. The catch-all `court_form_or_other_document` stays in forms unless the URL path says `judge-orders`, `general-orders` or `local-rules` (184 records moved to rules, basis names the segment; D09).
  - judge_enrichment / judge_entities / judge_vendor: always `judges` (D10). Other datasets: `classify(resource_kind)`.
  - Focused judge rosters/directories keep `directories` as primary and add `judges` as a secondary membership.
- `review_state` / `review_basis` (D01): reviewed, needs_content_review, title_evidence_only, not_applicable. `reviewed` means the retained record carries a positive body/structure verification (focused `body_status` verified/observed..., seeger structured provisions); `needs_content_review` reproduces the source's own flag (focused content_kind, unreviewed/to_verify kinds, pending publication); `title_evidence_only` = the kind rests on a title/catalog hint (seeger originals, focused title-evidence records); `not_applicable` = judge records, observed links, directory/navigation pages, provider profiles. It is never a legal review by this project.
- `doc_subtype` / `subtype_basis` (D09): form, order, rule, instructions_guide, fee_schedule, jury_instruction, notice, other - from an explicit keyword table applied to the title, then the source filename, then URL path segments (`/forms/`, `judge-orders`, `/rules/`, ...); defaults are stated in the basis (e.g. `court_rule_or_order` without an order keyword -> rule). Null where no subtype rule applies.
- `record_type` / `record_type_basis` (D08): law_provision, law_document, court_rule, order, form, court_document, directory_page, county_page, judge_observation, judge_profile, source_reference, guidance, notice, other - dataset rule + retained kind + derived category/subtype.
- `representation` / `representation_basis`: original_document, saved_page, structured_provision, source_observation, profile, observed_link, dataset_row, provider_capture (seeger `metadata.record_type` verbatim; focused `capture_kind` + file type; etc.).
- `file_type` / `file_type_basis` (D08): from the saved original's suffix, else magic bytes (the 554 `.bin` originals: 398 docx, 152 xml, 2 zip, 1 other), else payload format/content_type; `none` = no saved file (federal observed links).
- `has_original`, `has_text`, `text_chars`, `bytes`, `bytes_basis`, `original_sha256`: `text_chars` is the byte length of the saved text file or the inline text length (an upper bound on characters); `bytes` from payload/metadata sizes or a stat of the saved original (shared source files such as the judge JSONL are marked as shared in the basis); `original_sha256` is the payload's recorded hash of the original (null for judge datasets that have no per-record original).
- `jurisdiction_level` / `jurisdiction_basis`, `state`, `states`, `multi_state`, `court_label_as_published` (D03): federal, state, county, territory, multi, unknown. Seeger values are copied verbatim from `metadata.source_jurisdictions` / `source_courts`; `state='Federal'` only when the record's own metadata says Federal (seeger `["Federal"]` 6,703; federal dataset `scope=federal` without a state label 275; judge records with `judge_system=federal` and no state). Multi-valued state strings (89 focused, 1 judge entity, 2 seeger) are flagged `multi_state=1` with the list in `states` and `state` null - never resolved. Territories (Guam, Northern Mariana Islands, Virgin Islands) are `territory`. Nothing is inferred from hostnames or court names.
- Dates (each with `*_basis`; `*_lo`/`*_hi` are comparable YYYY-MM-DD bounds for partial precision, month/year values expand to their first/last day, timestamps use their UTC date): `saved_at` (+ `saved_at_field`) and `captured_at` come from `document_dates()` = `captured_at`, else the collector's `retrieved_at` with its `retrieval_time_basis`; `source_as_of` from explicit `source_as_of/as_of_date/as_of/source_date/snapshot_date` fields (19 records); `effective_from` only from `effective_date` fields or a seeger `source_date` whose `source_date_kind` says effective (5 records); `published_at` only from `judge_vendor.source_published_at` (1); `effective_to` always null (no evidence). HTTP Last-Modified is never used (checked). Seven-digit fractional seconds are trimmed to six before parsing (the reused helper rejects them otherwise).
- `publisher_status` / `publisher_status_basis`: seeger `metadata.source_status` (repealed, abrogated, renumbered, ...) or focused historical notice kinds, verbatim.
- `title`, `display_title`, `title_basis`, `title_issue`, `title_evidence` (D07): `title` is the retained record title. `title_issue` names the problem (url 3,465; boilerplate 701 = a title shared by >= 5 focused/pending records; placeholder 316 such as `[DOCX text]`/`[OCR]`; generic 90 such as `Home`/`PDF`; producer_prefix 46 `Microsoft Word - ...`). For those, `display_title` is derived only from saved evidence in this order: page/document markup (`<title>`, `<o:Title>`, `<dc:title>`, first h1/h2) or the saved text's first citation line (section/chapter/title/rule/article patterns) or first heading line (short consecutive PDF lines are joined, site-wide lines of the same host and navigation words are excluded), else the de-slugged source filename, else host + path. `title_evidence` is a path-free JSON note (source, line number, sha256 of the file read, excerpt). Basis counts: citation line 2,860; first heading line 481; de-slugged filename 417; page first heading 406; document `<o:Title>` 150; host + path 147; host 107; `<title>` 4.
- `validity` / `validity_reason` / `capture_flags` (D06): ok 57,583; no_capture 576 (federal observed links); parked_redirect 93; spa_shell 31; redirect_stub 12; empty 9; error_page 5; challenge 1. Exact shell hashes from `_inspect/explore_shells.json` come first (the 114-byte `/lander` redirect shared by 93 records across 89 hosts, the South Dakota "Loading..." shell, easyDNS parked page, IIS default page, zero-byte captures, ...), then markup/size/text thresholds for html originals under 8 KB (parked-domain text, script/meta refresh, frameset, challenge markup, default-server pages, `Loading...` with no text, < 512 bytes with < 40 text chars). `capture_flags`: zero_bytes, under_1kb, no_text, shared_hash_multi_host, shared_original, ocr, provider_capture, ineligible, multi_state.
- `wrong_county_joins` (D06): every `record_counties` row of a record whose capture is a shell/parked/empty/error/challenge page: 4,919 rows for 116 records (4,889 of them from the single `/lander` hash across 93 records). Reason strings name the validity, the shell and how many records/hosts share the hash.
- `label_source`, `court_id`, `label_county_geoid`, `law_body_class`, `rule_set`, `topics`, `label_doc_subtype`: folded from `sources/law_tier_20260919` because its `validation.json` was `passed`/`ready` at build time (hashes verified and listed under `inputs`): `law_body_class` for 10,013 records, `rule_set` for 953, `topics` for the 134 topic-index rows keyed by a directory record id (the other 17,808 topic rows describe Open US Law provisions, not directory records). `court_id`, `label_county_geoid` and `label_doc_subtype` are not provided by law_tier and stay null.

## Limits (what this sidecar does not do)

- Labels are rule-based over retained fields and saved evidence; they do not certify legal currency, completeness or content correctness. `reviewed` means the source's own verification signal, not a review by this project.
- Subtypes and derived titles are keyword/heading heuristics: a "Notice of Appeal" blank is labelled `notice`, some PDF headings are truncated to the first six tokens, index pages fall back to host + path (e.g. 49 Florida statute index pages), and about 25 Oregon pages pick up a numbering explanation line as their heading. The basis and evidence columns make every such case visible; the retained title is always kept.
- `text_chars` is a byte count, not a character count; `bytes` for records sharing one source file is the shared file's size.
- Jurisdiction is only as explicit as the record: 1,314 seeger structured provisions and 3,709 judge records stay `unknown`; multi-state associations are flagged, not resolved; `court_id` is not derived.
- Validity heuristics only inspect html originals under 8 KB beyond the exact hash list; larger soft-404s or challenge pages with generic titles are not detected here.
- Dates are never inferred from filenames, index times or HTTP headers, so most records have only a saved/captured date.
- The sidecar is a supplement: the server is not wired to it yet (see `integration_spec.json`); `directory.sqlite3` is unchanged.

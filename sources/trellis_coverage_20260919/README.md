# Trellis coverage supplement

This is publisher-reported coverage metadata for internal research use, not for redistribution. It is separate from saved document counts, Census county completeness and current authoritative court information.

`build.py` normalizes the 27 saved state responses, the directly saved Middlesex NJ county-detail scout wrapper, explicitly allowlisted browser batches, the historical Trellis catalog, and a passed incremental checkpoint from `sources/trellis_county_firecrawl_20260919`. It makes no network or paid-view calls. The original 33-entry call log has four calls without retained responses (IA, KS, KY, ME); these stay in `gaps.json`. Alabama's error response remains an error, not successful state coverage. Missing state-response records are never manufactured. The latest exact counts are in `validation.json` and `progress.json`.

State files emitted through `write_state_response.py` are labeled agent-transcribed connector payloads. New Jersey matches the text inside the separately retained scout wrapper byte-for-byte and is labeled accordingly. The Middlesex wrapper and browser DOM representations retain their distinct kinds. None is original HTTP content. Existing raw files and source browser batches are unchanged; browser DOM snapshots are copied into this supplement for stable receipt serving.

County FIPS joins require an explicit county name plus state in the saved current inventory. Provider and historical profiles additionally require the observed parent link label, matching profile heading, and state evidence in page metadata. Only the exact trailing navigation suffix “Dockets” is removed from parent labels; city and county remain distinct. Unresolved names include Delaware's Court of Chancery, Connecticut's eight historical counties, and spelling/diacritic mismatches. No current county equivalents are guessed. Browser records require exact GEOID/name/state, passed scope/dedup receipts and matching raw/text/metadata hashes. State context rows from browser, provider or catalog pages have null connector coverage flags. All 45 saved state-page contexts are retained separately from the 27 connector responses.

The current Firecrawl source is a selected rendered profile section in provider JSON, never browser DOM or original HTTP bytes. Raw JSON, text and HTML hashes, exact response URL/status, parsed fields, observed parent source and queue membership are checked independently. Immutable copies of provider JSON and checkpoint receipts are served from this sidecar. The collector can continue after a checkpoint; queue exhaustion and successful capture completeness are separate flags.

The sole additional provider allowlist is `sources/trellis_county_offline_supplement_20260919`, for separately validated offline recovery from retained responses. Its own manifest must pass the same identity/hash checks and may not duplicate an already accepted primary URL. Its artifacts may reference only the original provider collection or that supplemental folder. Original paid-batch manifests remain frozen; recovery counts are reported separately and no additional request is made by this builder.

Historical catalog originals are freshly hashed against the catalog before normalization. Compact extracted-profile receipts retain that original hash, path, size, observation date, fields and identity proof. These receipts are explicitly derived JSON, not the original response; the original files remain unchanged in the archive. New browser and provider details take priority, while all historical detail sources remain attached. Empty or unidentifiable old profiles remain recorded gaps instead of invented content.

`publisher_reported` contains population, seat, phone_number, administration_address, website, name_meaning and other source-provided fields. Numeric-looking strings remain verbatim; missing fields remain null. Website values use the observed href, not truncated display text. Administration addresses are never converted to courthouse addresses. `detail_sources` retains each receipt and its kind. Field currency, official-site authority and court territory are not independently verified. Empty courthouse arrays/zero counts and has_documents flags are publisher data, not proof of zero real courthouses or downloaded files.

Dates: state `captured_at` comes from the saved call log with its clock-reading qualification. Browser capture dates come from the browser observation. The scout county wrapper has no retained per-call timestamp, so its captured_at is null. Source-as-of, publication and legal effective dates remain null throughout unless explicitly evidenced.

Adapter contract: `summary()`, `state('TX')`, `county(fips='48241')` or `county(state='TX',name='Jasper County')`, and `listing(state,detail,has_documents,practice_area,venue,fips_resolved,q,limit,offset)`. Listing is offset-based and caps limit at 500. Unknown or ambiguous identity returns null. `receipt(id)` returns hash-verified immutable bytes, MIME and public metadata; no client-supplied filesystem path is opened. Public objects omit local paths.

`progress(state=None)` reports observed/saved/remaining unique profile URLs, exact remaining URLs, percent, and separately the count of distinct resolved county GEOIDs with details. Its observed inventory excludes three proven website-link extraction artifacts (Harrison TX and Allegheny/Delaware PA). This is not a denominator for all Census counties or case files. Per-state lookup accepts a code, full state name or state slug.

`validation.json` uses the uniform supplement envelope: status passed, boolean ready, and SHA-256 for every normalized data file and served source receipt. A fully verified snapshot is cached behind file identity/size/nanosecond timestamp checks for the gate, normalized files and receipts. Changed or missing evidence invalidates the cache and fails closed unless revalidation succeeds. Receipt downloads independently hash the exact bytes returned. This layer does not rebuild the main directory database or alter source facets.
